# Границы стартового каркаса

`apps/mobile/` — отдельный npm-проект, не копия существующего `src/` сайта. У него
свой lockfile, порт разработки, TypeScript, линтер и native-проекты. Код сайта,
браузерная демо-админка и Telegram Mini App не импортируются в mobile runtime.

Порядок подключения будущих частей:

1. Общие дизайн-токены, компоненты, переводы и доступность.
2. Публичный HTTPS API, обработка ошибок и безопасное хранение сессии.
3. Авторизация, профиль и права покупателя/продавца на сервере.
4. Каталог, магазины, поиск, избранное и состояние корзины.
5. Оформление по продавцам, серверные заказы и история статусов.
6. Сообщения и push с реальной доставкой между устройствами.
7. Разрешения, native-интеграции, тестирование и сборки для магазинов.

Страницы из `src/features/*/pages/` сейчас используют общий `FeaturePlaceholder`.
Это намеренные места под интерфейсы, не готовые операции и не тестовые данные
реальных пользователей. Папки `api/`, `components/`, `hooks/`, `types/` внутри
разделов оставлены для реализации соответствующего домена.

`src/services/` содержит места для внешних интеграций. Доступ к серверным данным
и проверка ролей должны выполняться API, а не условием в React-маршруте.
API-ответы и модели существующего сайта нужно согласовать до реализации запросов.

HashRouter выбран для предсказуемой навигации в bundled Capacitor web view.
`base: './'` сохраняет относительные адреса ресурсов. Нижняя навигация и контент
учитывают safe-area; будущие native deep links и Android BackButton подключаются
отдельно при реализации поведения приложения.

В `capacitor.config.ts` задан `webDir: 'dist'`, без удалённого `server.url`.
`cap sync` копирует web-сборку в обе оболочки; сами web-копии и native build-
результаты не являются исходным кодом и исключаются из Git.
